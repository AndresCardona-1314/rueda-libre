## Solicitud HTTP

- **URL completa:** `http://127.0.0.1:5500/index.html`
- **Protocolo:** `http://`
- **Host:** `127.0.0.1`
- **Puerto:** `5500`
- **Ruta:** `/index.html`
- **Método de petición:** `GET`
- **Código de estado:** `304 Not Modified`

## RUTA inesistente

Al direccionar la página a una página inesistente se genera el error `404 Not Found`, que basicamente significa que la página no fue encontrada.

## ROLES

### Rol HTML

El rol que cumplirá html es el de generar la estructura base de la página web para que luego el navegador pueda traducir dicho lenguaje. Es decir acá se estrutura todo el encabezado y cuerpo de la pagina(s).

### Rol CSS

El rol de CSS es pulir y darle una mejor apariencia a la pagina web. Es decir, elegir paleta de colores y tipo de letra.

### Rol JavaScript

El rol de JavaScript es todo el código base de lo que queremos que suceda con cada acción que se ejecute dentro de la página.

## Especificidad de selectores

**Problema:** el enlace con clase `.activo` no cambia a verde.

| Selector  | ID | Clase | Etiqueta | Especificidad |
|-----------|----|-------|----------|---------------|
| `#menu a` | 1  | 0     | 1        | (1, 0, 1)     |
| `.activo` | 0  | 1     | 0        | (0, 1, 0)     |

**Causa:** `#menu a` tiene mayor especificidad porque contiene un ID, y un ID pesa más que una clase. Por eso su `color` (gris-asfalto) gana sobre el de `.activo` (verde-ruta). En DevTools, la declaración `color` de `.activo` aparece tachada en el panel Styles.

## Medición de box-sizing en una tarjeta

**Elemento medido:** `<article class="tarjeta">` en index.html
**Condiciones de prueba:** `flex: none; width: 300px` aplicados temporalmente en DevTools.

| Caso                  | width | padding (izq+der) | border (izq+der) | Ancho total |
|-----------------------|-------|-------------------|------------------|-------------|
| Antes: `content-box`  | 300px | 32px              | 4px              | 336px       |
| Después: `border-box` | 300px | 32px (incluido)   | 4px (incluido)   | 300px       |

**Conclusión:** con `content-box` el relleno y el borde se suman al `width` y la tarjeta mide más de lo declarado. Con `border-box` el `width` incluye ambos y la tarjeta mide exactamente lo declarado, lo que hace los cálculos de diseño más predecibles.

## Uso de flex y/o grid

### Portada

- **Modelo utilizado:** Grid.
- **Selector y ubicación:** `.portada-principal`, definido en `css/styles.css` y aplicado a la portada principal de `index.html`.
- **Justificación:** Grid permite dividir la portada en columnas y distribuir el texto y la imagen como áreas independientes. La propiedad `repeat(auto-fit, minmax(min(100%, 15rem), 1fr))` ajusta automáticamente el número de columnas y permite que el contenido se apile al reducir el ancho disponible. También se usan `justify-content: center` y `align-items: center` para centrar ambos elementos.

### Galería

- **Modelo utilizado:** Grid.
- **Selectores y ubicación:** `.flota-bicicletas` para la galería de bicicletas y `.lista-rutas` para la galería de rutas, ambos definidos en `css/styles.css` y aplicados en `index.html`.
- **Justificación:** Grid es adecuado porque las galerías requieren varias tarjetas organizadas visualmente en filas y columnas. Con `auto-fit` y un mínimo de `15rem`, el navegador crea automáticamente 3 columnas en pantallas amplias y 1 columna cuando el ancho es pequeño. Dentro de cada tarjeta se mantiene Flexbox en columna para colocar el botón al final.

### Reservas

- **Modelo utilizado:** Grid.
- **Selector y ubicación:** `.formulario-reserva`, definido en `css/styles.css` y aplicado al contenedor principal del formulario y la información complementaria en `paginas/reservas.html`.
- **Justificación:** Grid organiza claramente el formulario y el apartado lateral en dos columnas con proporción `2fr 1fr`. Es una estructura de dos áreas con tamaños definidos, por lo que Grid ofrece mejor control que Flexbox para distribuir el ancho principal y secundario.

### Fila del formulario

- **Modelo utilizado:** Flexbox.
- **Selector y ubicación:** `.formulario-reserva-datos`, definido en `css/styles.css` y aplicado a la fila de identificación y celular en `paginas/reservas.html`.
- **Justificación:** Flexbox distribuye los dos campos horizontalmente dentro de una sola fila y permite que se ajusten o envuelvan con `flex-wrap: wrap`. `justify-content: space-between` separa los campos, mientras que `gap` conserva el espacio entre ellos.

### Encabezado

- **Modelo utilizado:** Flexbox.
- **Selector y ubicación:** `.barra-superior`, definido en `css/styles.css` y aplicado al encabezado de todas las páginas.
- **Justificación:** El encabezado contiene dos elementos principales: la marca y el menú. Flexbox permite ubicarlos en los extremos mediante `justify-content: space-between`, centrarlos verticalmente y hacerlos pasar a otra línea con `flex-wrap: wrap` si no hay espacio suficiente.

### Pie de pagina

- **Modelo utilizado:** Flexbox.
- **Selector y ubicación:** `.pie-pagina`, definido en `css/styles.css` y aplicado al `footer` de las páginas principales, de tarifas y de reservas.
- **Justificación:** Flexbox distribuye las secciones informativas del pie en una fila, las centra verticalmente y permite envolverlas cuando el ancho disminuye. `justify-content: space-evenly` reparte el espacio entre nombre, contacto, horarios y enlaces, según la página correspondiente.

## Pruebas responsive

Se realizaron las pruebas con la herramienta de dispositivos del navegador DevTools en las páginas `index.html`, `paginas/reservas.html` y `paginas/tarifas.html`. Los anchos probados fueron **360 px, 768 px y 1280 px**. En cada tamaño se verificó el desbordamiento horizontal, la distribución del encabezado y el pie, las columnas de las galerías, el formulario y las tablas.

### Resultados por ancho

| Ancho | Comportamiento verificado | Resultado |
| --- | --- | --- |
| 360 px | Encabezado, menú, galerías, formulario, tablas y pie | No se encontró desbordamiento horizontal; las tarjetas, rutas y campos quedaron en una sola columna. |
| 768 px | Encabezado, menú, galerías, formulario, tablas y pie | El encabezado recuperó una fila, las galerías mostraron dos columnas y el formulario quedó en una columna principal. |
| 1280 px | Encabezado, menú, galerías, formulario, tablas y pie | El contenido principal quedó centrado, las rutas y la flota mostraron tres columnas, el formulario quedó dividido en `2fr 1fr` y las tablas ocuparon el contenedor sin desbordarse. |

### Problemas encontrados y solución

1. **El encabezado ocupaba poco espacio o se comprimía en pantallas móviles (360 px).**
   - Se encontró una estructura horizontal no preparada para los enlaces del menú cuando el ancho era reducido.
   - Se resolvió con `.barra-superior { flex-direction: column; align-items: center; }`, `#menu ul { flex-wrap: wrap; justify-content: center; }` y el salto a una fila mediante el media query desde **768 px**. Así el menú se mantiene centrado en móvil y vuelve a ocupar los extremos en tablet y escritorio.

2. **Las galerías podían mostrar tarjetas demasiado estrechas o conservar un número inadecuado de columnas.**
   - En 360 px se necesitaba una columna para conservar la legibilidad; en 768 px dos columnas resultaban apropiadas; desde 1200 px las rutas podían mostrar tres columnas.
   - Se resolvió usando una cuadrícula de una columna por defecto, `repeat(2, 1fr)` desde 768 px para `.lista-rutas` y la flota adaptable, y `repeat(3, 1fr)` desde 1200 px para las rutas.

3. **El formulario y la información complementaria estaban pensados para escritorio y podían quedar excesivamente estrechos en móvil o tablet.**
   - En 360 px y 768 px el contenedor principal debía ocupar una sola columna; a 1280 px debía separar el formulario y el aside.
   - Se resolvió configurando `.formulario-reserva` inicialmente en una columna, cambiando la fila de identificación y celular a columna en móvil y fila flexible desde 768 px, y usando dos columnas con `2fr 1fr` desde 1200 px.

4. **Las tablas de tarifas podían resultar difíciles de leer en 360 px.**
   - Al reducirse el ancho, varias columnas y textos podían comprimir el contenido y provocar desbordamiento horizontal.
   - Se resolvió reduciendo el padding y el tamaño de fuente en móvil, utilizando `overflow-wrap: anywhere` en `th` y `td`, `width: 100%` en las tablas y ajustando el tamaño y espaciado desde el breakpoint de 768 px. La prueba mostró tablas de 297 px de ancho en 360 px, sin desbordamiento respecto al contenedor.


### Verificación final

Se verificó que las tres páginas probadas tienen `scrollWidth === clientWidth` en los anchos **360 px, 768 px y 1280 px**; es decir, no existe desbordamiento horizontal de la página. La prueba confirmó además:

- 360 px: una columna en galerías y formulario, menú y pie apilados.
- 768 px: encabezado horizontal, dos columnas en las galerías y pie distribuido en fila.
- 1280 px: contenido centrado con ancho máximo, tres columnas en rutas, tres columnas en la flota y formulario principal dividido en dos áreas.

## Flota con bootstrap


### Registro comparativo: CSS propio frente a Bootstrap

| Tiempo                  | Líneas    |
|-------------------------|-----------|
| CSS propio: 120 minutos | 34 líneas |
| Bootstrap: 20 minutos   | 8 líneas  |

**NOTA**: Se cuentan 8 líneas aproximadamente por articulo en las cuales se pueden añadir diferentes clases (diseños)   

#### Qué dio Bootstrap sin esfuerzo

- Creó desde el principio una cuadrícula adaptable con columnas y `g-4`, sin escribir las reglas manuales de `grid-template-columns`, `gap` ni los cálculos de ajuste automático.
- Facilitó los breakpoints con `col-md-6`, `col-lg-4` y `col-xl-3`, permitiendo mostrar 1, 2, 3 y 4 columnas según el ancho.
- Entregó utilidades listas para usar en espacio, alineación, flexbox, bordes, redondeado, fondo, altura completa, proporción de imágenes y botones.
- Permitió crear tarjetas uniformes con `h-100`, `d-flex`, `flex-column` y mantener los botones al final de cada tarjeta con `mt-auto`.
- Redujo la cantidad de reglas CSS propias necesarias para la distribución y presentación básica de la flota.
- Mejoró la velocidad de desarrollo: gran parte del diseño se describe directamente en las clases del HTML.

#### Qué control se perdió

- Se perdió parte del control directo sobre las reglas de distribución y los números exactos de cada grid, porque Bootstrap decide cómo se calculan las columnas y sus espacios.
- Se perdió independencia visual respecto al sistema predeterminado de Bootstrap: colores, bordes, tipografía, botones y espaciados dependen de las variables y componentes del framework.
- Se necesita conocer la convención de nombres y la combinación exacta de clases de Bootstrap; una clase adicional, mal escrita o no cargada puede cambiar o eliminar la apariencia esperada.
- La lectura del HTML resulta más larga y puede volverse menos semántica, porque varias responsabilidades visuales quedan repetidas dentro de los atributos `class`.
- La personalización más profunda requiere sobrescribir estilos de Bootstrap o ajustar variables, lo que puede generar conflictos con reglas generales y mayor especificidad.

## Clases utilizadas de bootstrap

- **`pt-3`**: aplica padding superior de tamaño 3. Pertenece a las utilidades de espaciado Bootstrap; su estructura combina padding (`p`) con el lado superior (`t`) y el tamaño (`3`). Se usa en los títulos de la sección de beneficios.
- **`text-center`**: centra el texto horizontalmente. Es una utilidad de alineación de texto de Bootstrap y se aplica, por ejemplo, a los títulos, párrafos y beneficios.
- **`fw-semibold`**: establece un grosor de fuente semibold. Pertenece a las utilidades `fw-*` de Bootstrap para modificar el peso tipográfico sin escribir una propiedad CSS manual.
- **`text-start`**: alinea el texto al inicio de su contenedor según la dirección de lectura. En este documento también es una utilidad responsive disponible desde cualquier tamaño de pantalla.
- **`d-none` / `d-md-block`**: `d-none` oculta un elemento y `d-md-block` lo muestra como bloque desde el breakpoint `md`. En la sección final, la combinación mantiene oculta la imagen decorativa en móvil y la muestra en pantallas medianas o mayores.

| Versión                                 | Líneas de css/styles.css | Tiempo invertido |
|-----------------------------------------|--------------------------|------------------|
| v1.5 — CSS propio (`4cc49cc`)           | 545                      | ___ minutos      |
| Versión actual — Bootstrap + CSS propio | 437                      | ___ minutos      |

## Ventajas de la v1.5 con CSS propio

- El diseño dependía únicamente de reglas escritas en el proyecto.
- Las cuadrículas y los breakpoints tenían nombres definidos por nosotros.
- Permitió aprender flexbox, media queries y distribución responsiva.
- El archivo dejó muy claro qué tamaños y colores pertenecen al proyecto.

## Desventajas de la v1.5 con CSS propio

- El archivo necesitó muchas más líneas.
- Las cuadrículas, márgenes y breakpoints debían escribirse manualmente.
- Existían más posibilidades de desbordamiento.
- Modificar una distribución en varias páginas requería revisar varias reglas.
- Repetir estructuras flexibles aumentaba el tiempo de desarrollo.

## Ventajas observadas con Bootstrap

- Permite crear columnas mediante `row` y `col-*`.
- Los breakpoints `md`, `lg` y `xl` ya están definidos.
- Reduce reglas duplicadas de distribución.
- Acelera la creación de formularios, contenedores y cuadrículas.
- Permite combinar utilidades y estilos propios.

## Desventajas observadas con Bootstrap

- El HTML contiene más clases.
- Algunas utilidades pueden reemplazar reglas visuales propias.
- Es necesario comprobar la cascada entre Bootstrap y `styles.css`.
- Bootstrap introduce estilos predeterminados que deben personalizarse.
- La cuadrícula no elimina la necesidad de revisar espacios, tamaños y accesibilidad.

## Conclusión

La versión v1.5 permitió construir la distribución completamente con CSS propio.
La versión actual conserva la identidad visual del proyecto y delega a Bootstrap
la distribución responsiva. Bootstrap reduce las líneas necesarias para organizar
contenedores y columnas, mientras que `styles.css` debe conservar únicamente
colores, tipografía, botones, tablas, tarjetas, formularios y estados visuales.
