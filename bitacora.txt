# Bitácora

## Solicitud HTTP

- **URL completa:** `http://127.0.0.1:5500/index.html`
- **Protocolo:** `http://`
- **Host:** `127.0.0.1`
- **Puerto:** `5500`
- **Ruta:** `/index.html`
- **Método de petición:** `GET`
- **Código de estado:** `304 Not Modified`

## RUTA inesistente

Al direccionar la página a una página inesistente se genera el error `404 Not Found`, que basicamente significa que la página no fue encontrada.

## ROLES

### Rol HTML

El rol que cumplirá html es el de generar la estructura base de la página web para que luego el navegador pueda traducir dicho lenguaje. Es decir acá se estrutura todo el encabezado y cuerpo de la pagina(s).

### Rol CSS

El rol de CSS es pulir y darle una mejor apariencia a la pagina web. Es decir, elegir paleta de colores y tipo de letra.

### Rol JavaScript

El rol de JavaScript es todo el código base de lo que queremos que suceda con cada acción que se ejecute dentro de la página.

## ESQUEMA DE REGIONES SEMÁNTICAS DE LAS PÁGINAS

Esquema previo a la modificación del código. Las etiquetas entre `< >` indican la estructura semántica propuesta.

### 1. Página principal — `index.html`

```html
<header>
  Logo, título "Rueda Libre", bienvenida y enlace para ir a "Encuéntranos"
</header>
<nav>
  Enlaces: Inicio, Tarifas y rutas, Reservar ahora
</nav>
<main>
  <section>¿Quiénes somos?</section>
  <section>Nuestros servicios
    <article>Alquiler de bicicletas</article>
    <article>Recorridos guiados por Medellín</article>
    <article>Taller de reparación y mantenimiento</article>
  </section>
  <section>¿Cómo alquilar tu bicicleta?</section>
  <aside>Beneficios del servicio (información complementaria relacionada con los servicios)</aside>
  <section id="encuentranos">Encuéntranos: dirección y correo de contacto</section>
</main>
<footer>
  Nombre del negocio, correo electrónico y derechos de autor
</footer>
```

## Justificación creación de formulario

- **Select:** Se utilizo el select/option debido a que es el que mejor se adaptaba para la parte de la selección de la bicicleta, tipo de plan y ruta. Es más amigable con una lista desplegable.
- **Input:** Se utilizo el input type="email" para generar una casilla que permita en ese campo solo datos que contengan la estructura estandar de una dirección de correo electrónico.
- **Input:** Se utilizo el input type="date" para generar una casilla que solo permitiera datos tipo fecha. Generando así una ventana emergente tipo calendario que a su vez solo permite colocar fechas dentro de un rango específico.

## Especificidad de selectores

**Problema:** el enlace con clase `.activo` no cambia a verde.

| Selector  | ID | Clase | Etiqueta | Especificidad |
|-----------|----|-------|----------|---------------|
| `#menu a` | 1  | 0     | 1        | (1, 0, 1)     |
| `.activo` | 0  | 1     | 0        | (0, 1, 0)     |

**Causa:** `#menu a` tiene mayor especificidad porque contiene un ID, y un ID pesa más que una clase. Por eso su `color` (gris-asfalto) gana sobre el de `.activo` (verde-ruta). En DevTools, la declaración `color` de `.activo` aparece tachada en el panel Styles.

## Medición de box-sizing en una tarjeta

**Elemento medido:** `<article class="tarjeta">` en index.html
**Condiciones de prueba:** `flex: none; width: 300px` aplicados temporalmente en DevTools.

| Caso                  | width | padding (izq+der) | border (izq+der) | Ancho total |
|-----------------------|-------|-------------------|------------------|-------------|
| Antes: `content-box`  | 300px | 32px              | 4px              | 336px       |
| Después: `border-box` | 300px | 32px (incluido)   | 4px (incluido)   | 300px       |

**Conclusión:** con `content-box` el relleno y el borde se suman al `width` y la tarjeta mide más de lo declarado. Con `border-box` el `width` incluye ambos y la tarjeta mide exactamente lo declarado, lo que hace los cálculos de diseño más predecibles.
